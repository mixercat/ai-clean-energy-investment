# Durian Price Forecast: Data Pipeline + Baseline

ส่วนข้อมูลของโปรเจค มี 3 ขั้น: รวบรวมข้อมูล → รวมเป็นตารางรายสัปดาห์ → ทดสอบโมเดลพยากรณ์ราคาขายส่งทุเรียน
ทำ 2 ชนิด: **หมอนทอง (W14021) เป็นตัวหลัก** พยากรณ์ 1/2/4 สัปดาห์ และ **ชะนี (W14020) เป็นตัวรอง** พยากรณ์ 1/2 สัปดาห์

## ติดตั้ง
```bash
pip install -r requirements.txt
```

## วิธีใช้

**0. วางไฟล์ราคา**
กดโหลด CSV จากหน้า data.moc.go.th/OpenData/GISProductPrice ทั้ง 4 ตัว (W14021, P14020, W14020, P14019) แล้ววางไว้ที่ `data/raw/moc/`
ชื่อไฟล์อะไรก็ได้ สคริปต์ดูรหัสสินค้าจากในไฟล์เอง ถ้าโหลดช่วงใหม่มาเพิ่มก็วางไว้ด้วยกันได้ แถวที่ซ้ำจะถูกตัดออก
(MOC API ตอนนี้ขึ้น error จึงใช้ไฟล์เป็นหลัก)

**1. รวบรวมข้อมูล**
```bash
python 1_fetch_data.py            # ทำเฉพาะที่ยังไม่มี
python 1_fetch_data.py --refresh  # ทำใหม่ทั้งหมด (ใช้หลังโหลด CSV ราคาชุดใหม่มา)
```
ได้ไฟล์ `data/raw/moc_<รหัส>.csv` (4 ไฟล์), `weather_daily.csv` และ `fx_cny_thb.csv` โดยอากาศกับค่าเงินดึงจาก API ให้อัตโนมัติ ต้องต่ออินเทอร์เน็ต

**2. รวมข้อมูล + เช็กว่าข้อมูลพอไหม**
```bash
python 2_build_features.py
```
แยกไฟล์ตามชนิด:
- `data/processed/weekly_features_<รหัส>.csv` ตารางรายสัปดาห์ 1 แถว = 1 สัปดาห์ (สิ้นสุดวันอาทิตย์)
- `outputs/data_report_<รหัส>.md` จำนวนฤดู สัปดาห์ต่อฤดู และสรุปว่าพอพยากรณ์ไหม
- `outputs/weekly_price_<รหัส>.png` กราฟราคาทุกปี **ดูกราฟนี้ก่อน** จะเห็นว่าฤดูอยู่ช่วงไหนและราคาเคลื่อนแบบไหน

**3. ทดสอบโมเดล**
```bash
python 3_baseline.py
```

## ทำอะไรกับข้อมูลบ้าง
| เรื่อง | วิธีจัดการ |
|---|---|
| ราคา 0 | แปลงเป็นค่าว่าง (0 = ไม่มีของขาย ไม่ใช่ราคาจริง) |
| ข้อมูลรายวันไม่ครบ | รวมเป็นรายสัปดาห์ ใช้ราคากลาง = (สูงสุด + ต่ำสุด) / 2 |
| ช่องว่างสั้น ≤ 2 สัปดาห์ | เติมด้วยค่าล่าสุด และมีคอลัมน์ `imputed` บอก |
| นอกฤดู | ไม่เติม ว่างเกิน 6 สัปดาห์ = จบฤดู (`season_id`) |
| อากาศ | เฉลี่ย 4 จังหวัด (จันทบุรี ระยอง ตราด ชุมพร) → ฝนสะสม 7/30/90 วัน, อุณหภูมิ, ความชื้น |
| ค่าเงิน | หยวน/บาท + % เปลี่ยนแปลง 4 สัปดาห์ |
| เทศกาลจีน | อีกกี่วันถึงตรุษจีน / ไหว้พระจันทร์ / วันชาติ + ช่วง 30 วันก่อนเทศกาล |

ตั้งค่าทั้งหมดอยู่ใน `config.py` เช่น จังหวัด, ช่วงก่อนเทศกาล, horizon

## อ่านผลยังไง (`outputs/`, ไฟล์รวมทั้ง 2 ชนิด มีคอลัมน์ `product_id`)
- **metrics.csv**: `MAE_baht` คือพลาดเฉลี่ยกี่บาท/กก. และ `better_than_naive_%` คือชนะวิธี "ราคาสัปดาห์หน้า = สัปดาห์นี้" กี่ % **ถ้าไม่ชนะ naive แปลว่าโมเดลยังไม่มีประโยชน์**
  - `interval_coverage_%` ควรใกล้ 80 ถ้าต่ำกว่ามาก แปลว่าช่วงราคาแคบเกินจริง
- **ablation.csv**: ตัดตัวแปรทีละกลุ่มแล้วดูว่า error เพิ่มไหม ใช้ตอบคำถาม "เทศกาลจีน/อากาศ/ค่าเงิน ช่วยจริงไหม" ความต่างเล็ก ๆ ไม่ถึง 1–2% ถือว่าเป็น noise อย่าสรุปเกินข้อมูล
- **latest_forecast.csv**: พยากรณ์จากสัปดาห์ล่าสุดที่มีราคาจริง พร้อมช่วงราคา 80% ส่วนนี้คือที่เว็บจะเอาไปแสดง
  คอลัมน์: `from_week, horizon_weeks, target_week, model, last_price, forecast, low_80, high_80, product_id, product`
- **backtest_h1_<รหัส>.png**: กราฟราคาจริงเทียบกับพยากรณ์ 1 สัปดาห์ 6 ฤดูล่าสุด

## หลักที่ใช้ (เอาไปเขียนในรายงานได้)
- **ไม่ให้ข้อมูลอนาคตรั่ว**: ตัวแปรทุกตัวเป็นค่าที่รู้ ณ สัปดาห์ที่พยากรณ์ ยกเว้นวันเทศกาลซึ่งรู้ล่วงหน้าอยู่แล้ว
- **ทดสอบแบบเดินหน้า**: train ด้วยฤดูก่อนหน้าทั้งหมด แล้ว test กับฤดูถัดไป
- **พยากรณ์ % การเปลี่ยนแปลง** แล้วแปลงกลับเป็นบาท ช่วยให้โมเดลใช้ได้แม้ระดับราคาแต่ละปีต่างกัน
- **ช่วงราคา** คำนวณจาก error จริงของโมเดลในฤดูก่อน ๆ

## ⚠️ สิ่งที่ยังไม่ได้ทดสอบกับของจริง
โค้ดทั้ง 3 ขั้นรันผ่านกับ **ข้อมูลจำลอง** แล้ว แต่ในเครื่องที่เขียนโค้ดต่ออินเทอร์เน็ตไปยัง API พวกนี้ไม่ได้ ตอนรันครั้งแรกให้เช็ก:
1. **ไฟล์ CSV จาก MOC**: ทดสอบกับไฟล์จำลองที่หัวคอลัมน์และรูปแบบวันที่ (`4/1/2010 12:00:00 AM` = 1 เม.ย.) ตรงกับไฟล์จริงแล้ว ถ้า error เรื่องคอลัมน์ สคริปต์จะบอกชื่อคอลัมน์ที่เจอ
2. **Open-Meteo / Frankfurter**: ไม่ต้องใช้ key ควรใช้ได้ทันที
3. **BOT API**: ตั้ง `FX_SOURCE = "bot"` ใน config แล้วตั้ง env `BOT_API_TOKEN` **ให้ตรวจ URL และชื่อ header จากเอกสารใน portal.api.bot.or.th** แล้วแก้ผ่าน env `BOT_FX_URL` / `BOT_AUTH_HEADER` ถ้าไม่ตรง
